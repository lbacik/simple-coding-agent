# Finish or preserve a paused rebase instead of aborting it

ADR 0001 made a workspace with an unresolved rebase the one exception to sealing: it was aborted rather than sealed, so conflict markers would never be committed. In #413 a model resolved and staged a deferred-setup conflict, never ran `git rebase --continue`, and kept working on the issue. The abort then threw away the whole attempt's work and left an untracked file that held intake for about 17.5 hours. We decided that when the model step ends with a rebase still paused, the runtime first captures all of the workspace (staged, unstaged and untracked) as a Preserved revision under `refs/agent/preserved/issue-<n>/<attempt-id>`. If no unmerged paths or conflict markers remain, it then finishes the rebase itself. The staged index completes the paused pick, the remaining changes are sealed as an attributed commit inserted mid-rebase, and `rebase --continue` runs until the rebase completes. The Preserved revision is dropped once the rebase succeeds. If the rebase cannot finish (leftover conflicts or markers, or a new conflict in a later pick), the runtime aborts, cleans the workspace without holding it, and reports `rebase_conflict` with the Preserved revision's ref. This applies to both implementation attempts and Conflict attempts. Separately, every abort of a paused rebase, on any path (including model-execution exceptions and cleanup), first keeps the workspace as a Preserved revision. The runtime finishes the rebase only on the normal path after the model step. An abort therefore never discards work. The rule that conflict markers are never committed still holds, because the runtime continues only when the marker check is clean.

## Considered Options

- **Stash, continue, pop.** Rejected: the stash also captures the staged resolution, and a conflicting pop leaves a second recovery problem.
- **Preserve and abort whenever the tree is dirty.** Rejected: nothing would be lost, but the #413 case would still need an operator for every occurrence.
- **A second bounded model step for a new conflict in a later pick.** Rejected: it adds a budget and limits for a rare case, and the next continuation retries the rebase from the kept work anyway.
