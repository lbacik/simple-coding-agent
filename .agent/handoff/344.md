## Summary

No code changes made; working tree clean. This was investigation-only: mapped the full
implementation surface for Sealed Attempt Archives + `attempts export`, and read the
external conformance suite (agent-operator-contract, public repo) as ground truth.

What was established:

- All finalization funnels through `AgentLifecycle._commit_finalization`
  (`simple_coding_agent/lifecycle.py:5742`): outcome write (`_write_outcome`) →
  PR backfill (`_backfill_archived_pull_request`) → completion ledger →
  `outcome_recorded` event → control finalization → `attempt_finished` event →
  checkpoint delete → telemetry finish. Normal, recovery-retry and recovery-release
  paths all end there. Startup reconcile of an already-ledger-finalized attempt only
  deletes the leftover checkpoint (no archive writes today).
- `attempt_history.py` is the read projection: `sealed` hardcoded `False`,
  manifest computed at read time, private-state filter in `_is_public_evidence`.
- `contract_adapter.py` already parses `attempts export <id> [--path ...]` but answers
  `unsupported`; no socket op / engine side exists yet.
- Socket replies are capped at 1 MiB (`_BUFFER_LIMIT` in `control_server.py`), so the
  tar cannot travel through the socket JSON reply. `agentctl` runs in-container
  (`docker exec`), so the CLI can read the volume — but it currently never touches
  the volume and has no DATA_DIR resolution (needs design; see below).
- `sealed` / `attempt_released` are in `CONTRACT_EVENT_NAMES` (pass-through) but nothing
  emits those natives today. The sealed event must reach the process ring + stdout with
  `attempt_id` but must NOT append to the sealed archive's `events.jsonl`.
  Complication: `JsonEventLogger.emit` resolves the archive from the *live checkpoint*,
  which is already deleted at seal time — so the sealed event needs explicit
  `attempt_id` plumbing (a small logger/lifecycle seam), not the issue_number sink.
- Conformance expectations (from `/tmp/contract/ps.py`, `tps.py`, `docs_mod.py` — only
  on the ephemeral box, re-download if needed): tar is uncompressed pax, first member
  `manifest.json` = `{"contract":"1.0","attempt":AttemptSummary,"files":[ManifestEntry]}`;
  sealed export must be byte-identical across reads; growing an unsealed archive must
  surface as size/sha256 mismatch; unknown attempt/path → `not_found` (exit 5) with no
  tar bytes; `sealed:true` requires non-null `sealed_at` and vice versa; `sealed` event
  with `attempt_id` must appear in `recent_events` after release.
- Open interpretation question: "released without a Terminal Outcome". Every
  in-repo path that ends an attempt records a terminal outcome via `_commit_finalization`
  (including recovery release with its inferred `actual_outcome`). The working theory:
  recovery-release is the "release" trigger and it seals via the same commit; if a
  truly outcome-less release path is found during implementation, seal it after its last
  write. Do not invent a new `released` lifecycle state unless the owner asks.

## Remaining work

1. **Sealing record** (new, in `attempt_history.py` or `observability.py`): after the
   finalization commit (post checkpoint-removal) compute the manifest over public
   evidence and atomically write one file (suggested `sealing.json`:
   `{"sealed_at": ..., "manifest": [...]}` via tmp+rename+fsync). Set-once: if the
   file exists, keep the existing `sealed_at`. Exclude the sealing file itself from
   manifests/exports (self-hash problem) with an explicit constant, not the dotfile rule.
2. **Post-seal write guard**: `AttemptArchive` write methods (`write_attempt`,
   `append_event`, `append_contract_event`, `write_text`, `copy_cli_transcripts`) must
   refuse when sealed (raise). This makes "any later write path is a defect" loud, and
   protects the startup-reconcile path. `read_attempt` stays allowed.
3. **Wire sealing into `_commit_finalization`** after `_attempt_state.delete()`: seal,
   then emit the sealed event. Add the logger seam so the event carries `attempt_id`
   without an archive append (e.g. `JsonEventLogger.emit` skips archive appends for
   sealed archives while still using the archive for `attempt_id` — but checkpoint is
   gone by then, so prefer an explicit `attempt_id` parameter threaded from lifecycle
   through `_event_log` or a dedicated lifecycle emit path). Native detail should be
   `attempt_id=<id>` (matches `_EXTRA_KEYS["sealed"]`).
4. **Reads**: `show_attempt`/`list_attempts` return stored manifest + `sealed:true` /
   `sealed_at` when the sealing record exists; computed moving snapshot otherwise.
   `sealed_at` must appear only after the PR backfill (it will, since sealing is last).
5. **Export**: new `export_attempt(data_dir, attempt_id, paths)` building an uncompressed
   pax tar (`tarfile`, `PAX_FORMAT`): `manifest.json` first, then one member per entry
   in manifest order. Manifest = stored snapshot for sealed, freshly computed for
   unsealed; file bytes are read live at stream time (tar header size = bytes actually
   read, so growth surfaces as size/sha256 mismatch). `--path` filters members AND the
   `files` list; unknown attempt or unknown path → `not_found` before any stdout bytes.
   Never include private state (reuse `_is_public_evidence`). Transcripts keep kind
   `transcript` at their `transcripts/...` paths; no engine-private files.
6. **Plumbing**: engine side `control_attempts_export` + socket op `attempts_export`
   (manifest/summary projection with active/held overlay, like show), and CLI-side tar
   streaming to `sys.stdout.buffer`. Decide volume access for the CLI (socket can't carry
   the tar: 1 MiB cap; offline needs volume-direct reads anyway). Keep stdout/stderr
   discipline: tar bytes only on stdout, nothing on stderr; errors are JSON envelopes.
7. **Tests** (TDD at the seams): sealing-record set-once; outcome-without-backfill =
   unsealed; recovery-release seals; recovery of an already-sealed attempt writes
   nothing (guard raises / reconcile only deletes checkpoint); export member order,
   `--path` filtering, `not_found` with zero tar bytes, no private files in export.
8. **Gates**: run `ruff check`, then `pytest` on 3.11 and 3.13 in order; then invoke the
   `code-review` skill (required even for small changes). Commit on the branch.
