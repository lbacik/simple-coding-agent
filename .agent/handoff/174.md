## Summary

Implemented the handoff-note `started_at` fix for issue #174 in three
commits on `agent/issue-174`. `model_execution.py`: all five handoff
prompt builders (`_cost_handoff_instruction`,
`_cost_handoff_followup_prompt`, `_operator_handoff_instruction`,
`_limit_handoff_followup_prompt`, `_operator_handoff_followup_prompt`)
take an optional `attempt_id` via a new `_attempt_id_sentence` helper
that names it as the verbatim `started_at` value, and `ModelExecutor`
stores it from a new optional `execute()` parameter used at all five
call sites. `lifecycle.py`: `_HandoffNoteValidation` carries an
optional `started_at_warning`, the validator no longer rejects on a
missing/malformed `started_at`, and a new `_emit_handoff_note_events`
helper emits WARNING `handoff_note_started_at_invalid` /
`handoff_note_rejected` at all five validation sites (live attempt,
recovery retry, recovery release, startup recovery, operator-note
fulfilment check). `ModelAttemptRunner` passes `attempt_id` to the
executor through a backward-compatible `_execute_model` helper.
`skills/handoff/SKILL.md` and `CONTEXT.md` now define `started_at` as
the attempt id. One small lint fix, tests, and review remain (below).

## Known issues

- The `_emit_handoff_note_events` helper is defined before
  `_HandoffNoteValidation` in `lifecycle.py` and annotates against it.
  This is safe only because the module has
  `from __future__ import annotations` (lazy annotations); if that import
  is ever removed the module will fail at import time. The continuation
  should confirm with a plain `python -c "import
  simple_coding_agent.lifecycle"` run.
- This note deliberately carries a non-ISO-8601 `started_at` (no attempt
  id was given in the handoff instruction that stopped this attempt, the
  exact gap this issue fixes). Under the old validator that would reject
  the note; under the committed new code it is warning-only. If the
  driving process validates with old code, expect `incomplete`.
- `python -m ruff format --check` reports a pre-existing formatting
  complaint at `lifecycle.py:51` (unrelated import block); leave it alone.
