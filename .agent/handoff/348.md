## Summary

Root-caused and fixed the halt hang that blocked the previous attempt, and
finished the remaining acceptance items except final verification.

**Halt-hang root cause (zombies, not a stuck daemon).** The smoke test
drives the harness in-process (`invoke()` → `run_harness`), so spawned
engines stay children of the pytest process, which never reaps them. An
exited engine is therefore a zombie, and `kill(pid, 0)` reports zombies as
alive — so `halt`'s 30s liveness wait always timed out even though the daemon
had consumed `halt_request.json` and exited, and every `stop-container`
burned its full 15s+5s waits (the ~102s smoke duration). Real multi-process
CLI use was unaffected (the setup CLI exits, init reaps). Fix in
`conformance_harness/harness.py`: keep `Popen` handles in a `_SPAWNED`
registry and reap in `_pid_gone` (`poll()` for our children, `waitpid`
probe with `ChildError` fallback to the signal probe for other processes'
engines). Temporary heartbeat instrumentation in `daemon.py` was removed
again after the diagnosis. A full-flow mirror of the smoke (in-process,
persistent dir) reproduced the hang before the fix; the post-fix mirror was
still running when this attempt ended.

**Smoke determinism + stronger offline asserts**
(`tests/test_conformance_harness.py`): removed the racy
`release`-before-`finish-attempt` (the attempt could finalize on its own
first → "no active attempt"; `finish-attempt` releases the hold itself, so
it is race-free against the held attempt). `release` True-path is now
covered deterministically via a `before-claim` hold; issue 7 is set
ineligible after finishing so the later `idle` is stable (no re-claim
churn). Offline reads now assert content: `rejected`/`instance_running`
while the engine is live; `paused` + `last_halt None` + intake closed after
`stop-container`; `paused` + `last_halt.reason == harness-smoke` after halt.
`_agentctl` now captures stdout; `_agentctl_json` parses the envelope.

**Dockerfile**: `base` + `harness` (adds `conformance_harness/` and
`tests/fakes.py` only, entry point `python -m conformance_harness`) +
`production` last, so the default build output is the historical image with
no fakes. No docker binary here, so image builds are unverified.

**Docs**: new `docs/conformance-harness.md` (verbs, state dir, image
targets, smoke command).

**Ruff**: fixed the baseline `F401` (`pytest` unused import); `ruff check`
passes.
