## Summary

Implemented structural (header-at-top plus block-level marker) matching for
attempt-result comments and handoff records to fix the #393 quoting bug.

- `recovery.py`: new `find_block_marker()` (marker alone on its own line,
  max three leading spaces/tabs, outside fenced blocks) and
  `AGENT_ATTEMPT_MARKER_PREFIX`; `is_attempt_result_comment()` requires a
  block-level `agent-attempt` marker with non-empty id;
  `is_conflict_attempt()` / `is_conflict_escalation()` require block-level
  markers; `is_handoff_record()` requires a block-level marker;
  `is_conflict_result_comment()` removed (no callers); header regexes
  tightened to `[ \t]{0,3}` so indented code blocks never match. Budget
  counting already gates on the structural helpers.
- `handoff_record.py`: `parse_handoff_record()` reuses `is_handoff_record()`
  plus `find_block_marker()` instead of duplicating the gate (no more private
  regex import).
- `lifecycle.py`: `_continuation_expected()` uses `is_attempt_result_comment()`
  with `kinds=("handoff", "incomplete")`.
- `github_tracker.py` / `tests/fakes.py`: `find_attempt_comment()` and
  `last_conflict_result_sha()` gated on structural helpers.
- `tests/test_quoted_result_headers.py`: 32 regression tests covering every
  acceptance criterion (quoting contexts, markerless headers, exclusions,
  prompt filtering, record quoting/ambiguity, budget quoting, rendered-body
  recognition, block-level marker rule, bare-marker shorthand).

Deliberately unchanged (see PR note): `is_pr_head_stale_notice()` stays
marker-anywhere (existing test pins it; stale-notice dedup matches the exact
full marker with specific shas, so quoting cannot false-positive), and
`find_attempt_comment()` pairs a top-anchored header check with the exact
marker bytes.
