## Summary

Implemented worker attribution on attempt-result comments. When `WORKER_ID` is set, every attempt-result comment (ordinary complete/incomplete/handoff/infrastructure-error via `_result_comment`, conflict attempts via `_conflict_result_comment`, and recovery-release via `release_comment_body`) carries a visible `Worker: <id>` line next to the outcome details and a hidden `<!-- agent-worker: <id> -->` marker next to the `agent-attempt` marker. Without `WORKER_ID` the comments render byte-for-byte as before. Existing marker parsing (`find_attempt_comment`, requeue-source, continuation counting) ignores the new marker by construction. New helpers live in `recovery.py` (`worker_marker`, `parse_agent_worker`, `worker_line`, `worker_blocks`); `worker_id: str = ""` added to both publication request dataclasses; all six lifecycle request/release sites feed `self._request_worker_id()`. The `code-review` skill was invoked (Standards: no hard violations; Spec: pass) and its cheap findings were applied (single `_request_worker_id()` seam, `worker_blocks` reuses `worker_line`, parser regex built from the marker-prefix constant).
