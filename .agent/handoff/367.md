## Summary

Randomised claim timing to break the whole-Pool lockstep (both Workers yield
the same issue every cycle). All three mechanisms implemented, always-on, no
config knobs, injectable `random_source` alongside the injectable `sleeper`:

- `github_tracker.py`: `CLAIM_LOST_BACKOFF_MAX_SECONDS = 2*SETTLE` constant;
  `_verify_claim` sleeps `random_source()*MAX` after `_yield_losing_claim`
  (covers next candidate in `claim_next` and FIFO fallback after lost
  priority); docstrings updated. Safety semantics untouched.
- `lifecycle.py`: `_poll_sleep_seconds()` (uniform ±20% of poll interval,
  rounded to 0.1s), `_startup_delay_seconds()` (uniform [0, poll/2], once,
  gated on `not done and not starting` so production's `starting=True`
  defers it past `mark_started`; retained-checkpoint reconciliation returns
  before it). `run_once` pre-draws the cycle's idle sleep (covers reconcile
  heartbeats + all hold messages, which now name the exact duration slept).
  `_gated_claim` signature unchanged.
- `tests/test_claim_timing.py` (new, 7 tests passing): two-Worker
  shared-login simulations (seed=1 converge in cycle 2 of bound 3, never
  both held) via `PoolTransport.freeze_verification` overlap modelling, plus
  back-off bounds/ordering, settle-exactness, jitter bounds + message match,
  startup once/before-first-claim, reconciliation undelayed.
- `tests/test_lifecycle.py` empty-queue test rewritten for spread+jitter.
- `tests/test_working_tree_hold.py` partially updated (`import random` +
  seeded `random_source` in helper only).
