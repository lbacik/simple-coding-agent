Local token estimator PROTOTYPE — throwaway

Question (ticket “Design the local token estimator”, map “Specify token-based attempt budgeting that works without live usage”): how does the agent count the tokens an implementation attempt has used while it runs, when the backend reports no usage for some or all of the model's responses? The model: every model response is counted as soon as it is seen, first as a local estimate (the thread's current context plus its visible output plus a thinking allowance), then replaced by the measured figure if the backend reports one. Threads that never report (Meta subagents) stay estimated. When the attempt ends, the total is reconciled with the authoritative ResultMessage.model_usage. The recorded scenarios replay real data: two #109 attempts (77 responses each, from CLI transcripts) and the #129 probe (main loop + one subagent).

Estimator settings

Fitted on the #109 transcripts: tool results ≈ 4.0 chars/token (IQR 3.6–4.2), visible output ≈ 3.0 chars/token, ≈ 60 tokens of framing per message, thinking ≈ 150–250 tokens per response (opaque on Meta). Main-thread base ≈ 19K tokens + prompt (the #109 agent); subagent base 1.4K is the probe's tool-light agent — unknown for Explore / general-purpose. Changing a setting restarts the current walkthrough.
